# 作業計画の最小書式

初回は目的と実行方針の確認に使い、承認後は同じファイルを更新する。
規模に応じて項目を同じ行へまとめてよい。長い別文書や機械的なチェックリストは不要。

## 承認済み方針（レビュー対象として凍結）

- 変更 ID / 計画の保存先 / 台帳の参照（既定の共有 Git ディレクトリ、または合意済み `--state-dir`）
- 目的・完了条件・対象外
- タスクと依存順序、担当サブエージェント、期待する成果物
- テスト・受け入れ条件、3 観点レビューの基準と資料の参照
- 初回の承認者・承認内容、以降の重要な判断とその理由

## 実行記録（比較対象から除外する範囲をレビュー資料に明記）

- 現在段階、完了した作業、検証結果、残るリスク、次の操作、保留中のホストへの依頼
- レビュー状態の参照: 同じ変更 ID の台帳 `status` を確認する。回数の別カウンターは作らない

実行記録は進捗・結果・状態参照だけを更新する。目的・範囲・条件・担当・判断の変更は
承認済み方針へ反映し、必要な再承認と新しいスナップショットのレビューを受ける。

計画には認証情報、claim トークン、個人情報、生の環境出力、レビュー資料本文を入れない。
参照先にも機密情報を埋め込まない。レビューの資料・結果・回数は既存の台帳方式で扱う。
同じ計画だけを更新し、別タスクのファイルや既存の repo 規約を置き換えない。
